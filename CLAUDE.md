# Workshop 4 — Claude Project Instructions

## Project

Build an academic workshop website titled:
"AI for Smart Grids and Renewable Energy Systems".

Target URL: https://dsl-uow.github.io/ai4smartgrids-workshop/

## Source of truth

1. docs/01-project-brief.md — requirements
2. docs/02-reference-audit.md — Workshop 3 findings
3. docs/03-content-inventory.md — approved content (edited in assets/js/content.js)
4. docs/04-design-spec.md — visual specification
5. docs/05-implementation-plan.md — implementation phases
6. docs/06-deployment-guide.md — Pages deployment
7. docs/07-decisions.md — recorded decisions

Do not treat proposals or placeholders as approved facts.
If documents conflict, stop and report the conflict.

## Required page sections

1. Hero: title, subtitle, date/time, location
2. About Workshop
3. Presenters
4. Schedule
5. Venue
6. About the Team
7. Footer

Preserve this logical order.

## Design principles

- Academic, professional and contemporary
- Reflect smart grids, AI and renewable energy
- Responsive and accessible
- Mobile-first implementation
- Minimal dependencies and fast loading
- Respect lab branding

## Technical rules

- Inspect [Workshop 3 before selecting a stack](https://dsl-uow.github.io/modern-se-in-ai-era-workshop-3/).
- Prefer a static website unless justified otherwise.
- Avoid root-relative asset paths.
- No backend unless explicitly approved.
- Do not introduce unnecessary frameworks.
- Keep configuration and dependencies minimal.

## Content rules

- Never invent presenters, affiliations, dates or venue.
- Use clearly marked placeholders for missing content.
- Do not copy third-party images without permission.
- Preserve supplied names, titles and affiliations exactly.
- Do not publish draft content as confirmed information.

## Workflow rules

- Inspect before editing.
- Explain planned changes before implementation.
- Work on one approved phase at a time.
- Do not deploy or push without approval.
- Do not force-push, reset or delete branches.
- Do not create commits unless requested.
- Run relevant checks after each implementation phase.
- Report files changed, tests run and unresolved issues.

## Documentation rules

- Keep documentation concise and consistent.
- Update implementation progress after each phase.
- Record important decisions in docs/07-decisions.md.
- Do not create additional documents unnecessarily.

## Definition of done

- All required sections exist.
- Layout works on mobile, tablet and desktop.
- Links, images and navigation work.
- Accessibility basics are verified.
- No fabricated workshop information.
- GitHub Pages deployment is verified.
- Professor-approved content is published.
